# ADR-0015：手柄反馈

[English](0015-controller-feedback.md)

相关：IN-12、IN-13、MAP-25、HUD-08、HUD-10、UI-27、SCR-23；[ARCHITECTURE](../ARCHITECTURE.zh-CN.md)；[ADR：脚本运行时](0010-scripting-runtime.zh-CN.md)；[ADR：输入](0002-input-sdl.zh-CN.md)

## 背景

手柄可以当状态指示器：层和暂停的脉冲与颜色、绑定触发时的触感、旋钮刻度、玩家灯、识别“是哪一只”、低电提醒。这些都写到同一只手柄上，会互相抢：一个 tick 不该把“切到第 3 层”的三下脉冲截成一下；脚本的效果不该比脚本活得长；2.4G 接收器不接输出报告时，一次阻塞写不该拖住所有手柄的输入。

## 决定

### 一、混音器统一仲裁
- 所有反馈经 `internal/haptic` 的混音器（纯包，每个输入源一个），不由调用方各自调度。这样才有一处保证退出时什么都不留。
- 震动按优先级类仲裁：Identify、Alert、Ambient（层与暂停）、Script、Event（绑定与旋钮）。新请求的类不低于正在跑的才抢占，否则丢弃。Event 类每设备限速，因为 Switch 驱动会合并震动写入。
- LED 和玩家灯每个类一个声明，最强的显示，定时图案结束后下面的露出来。SDL 没有“把灯还给手柄”的调用，所以没有声明剩下时给彩色 LED 设黑色。
- 错误冷却按组（震动、LED、玩家灯），一次失败只停那一组。
- **对应不变量 1：** `Cancel`、`Stop`、`StopAll` 以零震动、LED 释放、玩家灯复原结束。除失联、关闭、暂停之外的所有退出路径都走到它们之一。
- 能力不够的调用不发，不是错误。效果队列投递永不阻塞，满了丢最旧的一次性效果，环境状态和取消不丢。

### 二、触感预设
- 预设名只有一个来源，profile schema、引擎和脚本 API 共用。强度是 `feedback.strength`，0 表示关。
- 触感是绑定的成员，不是动作的，意图是“这个键按下去有手感”。引擎在声明式手势的唯一分发点调一次回调，脚本接管的手势和暂停中都不响。旋钮刻度被限速挡下的不响。

### 三、识别手柄（IN-13）
识别是用户的明确操作：不看任何开关和暂停，对没映射的手柄也有效，并清除错误冷却再试。守护进程要求明确的 `device`，只连着一只时由命令行替用户选。不经效果队列，因为它要返回答案（震动、LED、玩家灯各自是否启动）。

玩家灯显示当前层的模式编号，不是 slot 编号，因为托盘角标和层脉冲说的也是模式。

### 四、四个全局反馈开关（UI-27）
- 震动、灯光、暂停提示、低电提醒存在 config.json 的 `feedback`，默认都开，立即生效，不重载配置、不放开按着的键。开关由开变关时，把它管的还在进行的东西停掉。
- 这些开关说的是手柄和用户，不是某个软件的映射，所以不按配置分。profile 里同名成员保留并标 `deprecated`，被解析、被忽略，不迁移。profile 的 `feedback` 里只剩时间、强度和暂停色。

### 五、电量与低电提醒（IN-12）
- 电量是动态数据，不放进设备信息。读取手柄加入时、接收器复活时、SDL 电量事件，另加每 30 s 保底。变化才发 `DevicePower` 事件，不给 slot，因为 slot 落后时会丢弃非关键边沿。
- XInput 的 charging 记作 `wired`：SDL 把 XInput 有线报成充电 100%，分不清。`unknown` 永远不提醒、不改变任何状态。
- 阈值固定不可配置：放电且 0 至 25% 提醒，充电、插线或达到 60% 重新布防。依据是驱动的粒度（XInput 只有 10、40、70、100 四档），60 高于提醒后下一档，电压回弹一档不会反复提醒。
- 状态按 DeviceKey 记着，接收器复活和换配置不会再提醒。开关关着时开始的 episode 也算，之后打开不补发。
- 三个渠道：手柄自己的 Alert 类、托盘气泡、浮层提示。都不抢焦点，因为画画时右手在数位板上，阻塞对话框不可取。

## 代价

- 接收器常丢掉所有输出报告，震动和灯光完全不出来，这不是 padmate 的缺陷，也无法绕开。真机效果需要核对。
- 通过接收器的手柄没有可靠电量，不显示也不提醒。

## 放弃的做法

- **事件优先于层脉冲。** 用户会数不对层。
- **全局冷却。** 一只手柄出问题不该让别的手柄哑掉。
- **给触感单独的强度或开关。** 用 `strength` 和 `rumble`。
- **每个配置各一份反馈开关。** 旧值残留会让全局开关“打不开”；迁移则可能矛盾，守护进程也不改写用户的文件。
- **把 XInput 的 charging 改成 unknown。** unknown 不重新布防，wired 才是“这个读数不是电量”。
- **自己开第二个 HID 句柄读电量。** SDL 已经解析了，多开句柄在 USB 接收器上有风险。
- **没有 `device` 时由守护进程挑唯一的手柄。** 同一个请求不该在一只和两只手柄时意思不同。
