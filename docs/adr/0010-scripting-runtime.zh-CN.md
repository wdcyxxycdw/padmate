# ADR-0010：脚本运行时

[English](0010-scripting-runtime.md)

相关：[ADR：引擎与线程](0005-engine-and-threads.zh-CN.md)

## 背景

脚本写声明式映射表达不了的逻辑：层、手势、连续输入、定时、反馈。约束：脚本和 JSON 绑定共用手势识别和输出；出错、被打断、被替换都不卡键；脚本路径端到端 p99 目标 3 ms；用 TypeScript 写，编辑器有类型提示。

## 决定

1. **goja + esbuild。** esbuild 的 Go API 把 TypeScript 打成 IIFE，交给进程内的 goja 执行，构建不需要 Node。构建结果按（源码哈希、esbuild 版本、API 版本）缓存，没有缓存的构建在 worker 上跑，slot loop 不等它。依据：缓存命中时激活 p99 0.86 ms，含构建 13.2 ms，超出 10 ms 目标。
2. **自研事件循环，嵌在 slot loop 里。** 不启动 goroutine，只保存定时器和微任务。时间只来自 `clock.Clock`，fake 时钟可以复现定时器和 Promise 的顺序。全局只有 `console`，定时用 `sleep`、`every`、`onTick`。
3. **看门狗按线程 CPU 时间计，不按墙钟。** 墙钟在 CPU 高负载时会误杀脚本，`GetThreadTimes` 的粒度（15.6 ms）又太粗，所以读 `QueryThreadCycleTime`。校准误差只会偏低，看门狗只会提前触发。宿主 API 必须快速返回，因为 `Interrupt` 打断不了 Go 原生函数。
4. **脚本与声明式映射共用识别器、Arbiter 和生命周期。** 脚本向引擎提供注册表和回调，纯引擎不导入脚本运行时。`holdKeys`、`holdLayer` 绑定到按压周期，周期结束或被取消时释放。脚本和声明式输出共用最短按压与同键间隔。
5. **冷启动输入先缓冲再回放。** 没有有效 Host 时（例如安全释放后第一次按键），命名动作会被丢弃，脚本手势也会错误回落到声明式绑定。slot 暂存最多 128 个边沿，就绪后按原顺序进入同一个识别器。溢出或冷启动失败时整批取消并释放。
6. **`script.api` 是 `0.N`，宿主同时支持当前和上一个 0.N。** 更早的版本被拒绝，不自动迁移，因为守护进程从不因为文件旧而改写文件。旧版本照常加载，校验给出升级警告。新版本只加成员、不带 shim，成员用 `@since` 标注，类型按 profile 的 API 过滤。1.0 不冻结脚本接口。
7. **浮层 API（0.16）。** 面板放在 runtime 里，随 state 事件的 slot 快照发布，不另设事件协议；runtime 不活动时不报面板，屏幕上不会留下已经不在的面板。顶层代码和 `setup` 里调用 `hud` 抛错，宏不能用 `hud`。
8. **手柄反馈 API（0.17）。** 参数错了抛 `TypeError`；手柄做不到或开关关着时是静默的空操作，所以稳定的只是名字、参数和“尽力而为”的语义，用 `host.has` 探测能力。脚本的强度不乘 `feedback.strength`。每个 runtime 限制每秒开始效果的次数，停止永远通过。runtime 不再活动时取消它放过的效果，新 runtime 激活前旧的先取消。
9. **序列与文字（0.21）。** `key.type`、`key.sequence` 规则与 profile 的 `sequence`、`text` 动作相同，每个字符和按键计入输出限流。

## 代价

- 缓存失效（改源码、升级 esbuild）后第一次激活要 11 至 21 ms。
- 没有 `setTimeout`，网上复制的代码要改写；d.ts 不声明它，编辑器会报错。
- 看门狗的校准没有上界，发现不了坏的校准。E 核上同样的预算只能做约 60% 的工作。AMD 和虚拟机上的 TSC 没有测。
- 计算出来的 `import()`/`require()` 路径会被 esbuild 当作 glob 展开，目录列举仍会发生，文件内容被拦住。
- goja 不支持而类型检查发现不了的东西（`using`、正则 `\p{…}` 和 `d`/`v` 标志、`Intl` 运行时、异步生成器对象）要脚本作者自己避开。
- 冷启动缓冲溢出时这一批按键丢失。
- 感觉类 API 的实际效果需要真机核对。

## 放弃的做法

- **goja_nodejs 的 eventloop。** 它自己拥有循环，slot loop 里会有两个唤醒源，fake 时钟也驱动不了。
- **只允许同步处理器。** `sleep`、按住一段时间再松开写不出来，用户会忙等，反而触发看门狗。
- **每次激活都构建。** p99 13 ms，超出目标。
- **每个宏或每个脚本一个 runtime。** 每个手柄多份 runtime、冷启动和看门狗，见[ADR：脚本宏](0011-script-macros.zh-CN.md)。
- **面板用 `hud` 事件做“加”和“删”，或新增 `hud.attach`。** 漏一条事件或重连就错，还得另做同步协议。
- **把脚本的震动乘 `feedback.strength`。** `strength` 是预设的主音量，用户要静音就关“震动”开关。
