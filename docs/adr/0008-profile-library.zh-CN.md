# ADR-0008：配置库、默认配置与按软件自动切换

[English](0008-profile-library.md)

相关：PRO-05、PRO-11、PRO-16、PRO-20、PRO-28、PRO-29、UI-18；[ARCHITECTURE §9](../ARCHITECTURE.zh-CN.md#9-前台检测)、[§10.1](../ARCHITECTURE.zh-CN.md#101-磁盘布局)；[ADR：配置文件格式](0007-profile-format.zh-CN.md)

## 背景

- 用户的用法是一个软件对应一个配置。没绑定的软件只应有一种结果。
- 前台变化来自 Win32 回调，磁盘读取和配置切换不能在消息线程或 slot 上做。
- 重启后要恢复层状态，但不能破坏释放所有键的边界。
- config.json 手改出错时，不能让用户自己修文件。

## 决定

1. **配置库。** 数据目录下 `profiles/<id>/profile.json`，每个配置一个文件夹（含脚本）。库 ID 是受限的小写 ASCII，显示名可用任意 Unicode。所有读取用 `os.Root`，拒绝越界链接。
2. **层状态按设备持久化。** `state.json` 按完整 DeviceKey 和库 ID 保存层选择；更换连接方式视为不同设备。按住键、锁存和定时器不落盘，恢复只恢复选择、不生成按键。后台定时刷盘；退出时在释放按键之后才最后写一次，慢磁盘不能推迟释放。
3. **自动切换只看规则。** 前台软件命中第一条启用的规则就用那个配置，否则用 `default`；按程序文件名（或完整路径）匹配，不读窗口标题。padmate 自己的窗口在前台时保持当前配置（UI-18）。
4. **前台检测不阻塞，也不猜。** 钩子只投递消息，进程路径在别处查询；查询失败时保留上次有效前台，过期结果不覆盖较新的。用户选择、自动选择与热重载串行化。
5. **切换配置永远释放旧 owner**，并隔离仍按着的控件；`releaseOnSwitch:"never"` 只关闭同配置的前台释放。旧脚本先停用，新脚本失败也不恢复旧脚本。
6. **显式 `--profile-id` 只决定起始配置。** 自动选择开着时，下一次前台评估仍按规则选择。
7. **窗口捕获（PRO-16）**用 `app.foreground` 和 `apps.recent`。
8. **固定默认配置（PRO-28）。** `default` 是保留 ID，没绑定的软件都用它；启动时缺它就建一个不映射的空配置；运行中被删掉或读不了，就按内置空配置运行并记警告。它不能删除、不能改名，其余照常。要让某软件不映射就给它绑一个空白配置。
9. **库操作都由守护进程执行**，界面的 Main 只碰用户选的那一个文件。
   - 删除不可恢复；正在使用或被引用的不能删；被继承的配置删除前先把子配置展开成完整内容。
   - 导出/导入单个配置（PRO-20）：`.padmate` zip；导入在写盘前检查全部内容，只收脚本、JSON 和文本；没有接受路径的 RPC。重名由客户端选“替换”或“另存为”。导入的 profile 不能带 `extends`。
   - 每次替换 profile.json 之前留一份历史快照，只作 CLI 后路。
10. **config.json 出错时自动修复（PRO-29）。** 先把原文件备份成 `config.broken-<时间>.json`（从不覆盖已有备份），再写修复版：保留合格成员，每个错误只重置包含它的最小成员；完全解析不了才整个换成默认。界面弹对话框给出备份名。读不了的 config.json（是文件夹、拒绝访问）仍是启动错误。state.json 出错静默重置。

## 代价

- 同名的不同程序共用一条规则，要区分需写完整路径。
- 没绑定的软件不再“保持当前配置”。在 padmate 里改的规则要等用户切到别的软件才起作用。
- 开发时 `--profile-id X --dry-run` 在自动选择开着时会马上换成默认配置；要固定就在 config.json 写 `"enabled":false`。
- 删除不能恢复，靠确认框兜底。
- 被修复改掉的设置要靠备份文件找回。
- 导入的脚本没有信任确认。
- 层状态按完整 DeviceKey 记忆，同一只手柄换了连接方式要重新设层。

## 放弃的做法

- **按顺序编辑的规则表（AntiMicroX）。** 用法只需要一对一。
- **保留 `onUnmatched`、不切换列表和按程序停用。** 控制流太多。
- **默认配置可删除、可改名或另用单独文件。** 删除后又回到“停用”的特例；单独的文件让编辑、脚本、历史另做一套。
- **padmate 窗口按普通程序处理。** 编辑时会切到别的配置。
- **切换设置重启后生效。** 用户以为绑定没成功。
- **Main 直接读写配置文件夹。** 检查要在两种语言各做一套。
- **用磁盘快照做撤销。** 快照按保存计，与一次编辑不对应；撤销在界面内存里。
- **坏的 config.json 只提示，或整个换成默认。** 前者要求用户改文件；后者因一个拼错的字段丢掉所有设置。
