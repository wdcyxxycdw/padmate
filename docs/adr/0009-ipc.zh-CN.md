# ADR-0009：IPC：命名管道上的 JSON-RPC

[English](0009-ipc.md)

相关：IPC-01、IPC-02、IPC-07、UI-02；[ARCHITECTURE §11](../ARCHITECTURE.zh-CN.md#11-ipc)

## 背景

`padmatectl` 和 Electron 界面都经 IPC 控制守护进程。能写 profile 就能让守护进程向前台发任意按键，所以 IPC 只对当前登录用户开放。另外要：Go 和 Node 都易实现；支持订阅推送；慢客户端不拖慢引擎；同一用户的其他进程抢先创建同名管道时骗不走 token。

## 决定

1. **命名管道 `\\.\pipe\padmate-<SID>`**（Go 侧 go-winio）。DACL 先拒绝网络登录再允许当前用户，顺序不能反；拒绝远程客户端；第一个实例用 `FILE_CREATE` 创建，同名管道已存在则守护进程退出。
2. **发现文件 `%LOCALAPPDATA%\padmate\run\daemon.json`**，含管道名、pid、协议版本和 token。只允许当前用户访问；token 每次启动重新生成。
3. **客户端先验证服务端，再发 token。** 核对管道服务端 PID 等于发现文件里的 pid，不符就断开，服务端收到零字节。Node 的管道接口做不到这一点，所以界面经 `padmatectl ui-bridge` 连接。
4. **JSON-RPC 2.0，NDJSON。** 事件推送用 `subscribe` 加通知，话题名就是通知的 method。第一条必须是 `hello{token, protocol, client}`，在启动 RPC 服务之前验证；首条错误、错 token、错协议、超长都直接断开。
5. **有界连接。** 帧、批、客户端数和握手时间都有上限。批内不保证顺序，客户端应等写操作的响应后再查询。
6. **背压：引擎永不阻塞。** 发布不做网络或磁盘 I/O；每连接一个有界事件队列，满了就丢并在恢复后发送 `dropped{n}`；独立 worker 发送，写超时断开。`daemon.exiting` 同步发布，最多等 250 ms。
7. **`protocol` 是整数**，破坏性变更时加一，与 `schemaVersion`、`script.api` 相互独立。
8. **IPC 之外的出口：** `padmatectl release-all` 不走 IPC（[ADR：不卡键](0006-no-stuck-keys.zh-CN.md)）。

## 代价

- 传输部分只能在 Windows 上测试。
- 高频话题靠有界队列和丢弃兜底，界面要处理 `dropped`。
- 同一用户的其他进程能读 daemon.json、也能连接，这在设计范围内：同一用户的进程本来就能 SendInput。
- 守护进程崩溃后 daemon.json 可能残留，客户端要处理“文件存在但连不上”。

## 放弃的做法

- **localhost TCP 或 WebSocket。** 本机任何用户的进程和浏览器网页都能连，只能靠 token，没有操作系统级访问控制。
- **gRPC。** 要引入 protobuf 和第二套代码生成，已有 JSON Schema → Go/TS 的生成链。
- **WM_COPYDATA 或 COM。** Electron 很难用。
- **客户端不校验服务端。** 同一用户的进程抢先创建同名管道，就能收到 token 并冒充守护进程。
