# ADR-0018：安装包与更新

[English](0018-installer-and-updates.md)

相关：[ARCHITECTURE §15](../ARCHITECTURE.zh-CN.md)；[ADR：进程与技术栈](0001-processes-and-stack.zh-CN.md)

## 背景

普通用户下载一个安装程序，不编辑任何文件，几分钟内让第一个快捷键到达绘画软件。约束：

- 安装、升级、卸载要停掉正在运行的守护进程而不卡键，也不能误杀别的 padmate（开发版、便携副本）。
- 卸载会删除整个安装目录，所以安装目录不能是装着别的东西的文件夹。
- 测安装、升级、卸载不能碰本机的真实状态。
- 用户大多在国内，访问不了 GitHub。

## 决定

### 一、PE 资源与便携包
编译后用纯 Go 的 `winres` 写入图标和版本资源，不在源码树生成 `.syso`，也不用 `rc.exe`（要额外装工具链）。便携包不是完整的便携模式，日志和状态仍用用户数据目录。

### 二、安装包（NSIS 向导）
- 用 electron-builder 打 NSIS 包。**只按当前用户安装，从不提权**：清单是 `asInvoker`，没有“所有用户”选项，`packageinstaller verify` 检查清单。
- **卸载项的 GUID 固定且永不修改**，换了就不再把旧安装当作同一个程序升级。
- 桌面快捷方式只在全新安装和手动覆盖安装时建，自动更新不建，所以用户删掉的不会在每次更新后回来。
- **安装目录。** 所选文件夹最后一段是 `padmate` 就是安装目录，否则装进其中的 `padmate` 子文件夹；补了子文件夹时停在页面上让用户再确认，装之前总能看到去哪里。静默安装的 `/D=` 原样使用。
- **目录守卫。** 目录必须是空的、已有 `padmate.exe` 或卸载程序，或就是注册表记着的安装目录。有别的文件时不动它。
- 安装前要试写，因为 electron-builder 先删旧版本再写新版本，写不进去会让用户两个版本都没有。
- 换目录升级时，对新旧目录各停一遍守护进程，再让旧卸载程序以 `--updated` 删除旧目录，用户数据不动。

### 三、停止守护进程
- IPC `daemon.exit` 参数必须恰为 `{reason:"installer"}`，走托盘“退出”的序列：先暂停映射并释放所有键。它不在界面的允许列表里，界面不能让守护进程退出。`padmatectl quit [--under DIR]` 请求退出并等进程消失。
- **安装程序的顺序：** 先 `quit`；只有 quit 失败才 `release-all`（它会让用户所有 `--inject` 的 padmated 释放键并销毁脚本，包括装在别处的）；再等 10 秒；仍在的才 `TerminateProcess`。结束 `padmated.exe` 前若没跑过 `release-all` 先跑一次，因为结束守护进程不会释放按着的键。
- **按映像路径找进程，不按名字。** 安装目录之外同名的程序不会被碰。不调用 taskkill、PowerShell、wmic。

### 四、卸载
只在完整卸载时清理，升级不动用户数据。**询问是否保留配置和脚本**，默认保留，因为那是用户花时间做的，删除不能撤销；静默卸载不问。登录启动项只在 Run 指向本安装目录时才删。

### 五、测试隔离
冒烟测试用 `PADMATE_INSTALLER_TEST_ROOT` 把 `%APPDATA%`、`%LOCALAPPDATA%` 和 Run 值换成测试目录，`quit` 用独立 IPC 目录，不运行 `release-all`。安装位置、卸载项和快捷方式仍写真实的，结束时删除；机器上已装 padmate 时拒绝运行。

### 六、签名
私钥和密码不经过 AI，仓库里不放证书。**默认不签**，没有证书时照样发布，文档写明 SmartScreen 的提示。有证书时 `app-update.yml` 要写 `publisherName`，否则 electron-updater 不校验签名。

### 七、杀软误报
低级键盘钩子只在 padmatectl 的“录入快捷键”时开着，最长 30 秒，只看不吞。离线 PE 检查（`task pe:check`）要求导入表和 API 列表等于提交的清单，新增 Windows API 评审时就能看到；注入类 API 永远不许出现。不自动扫描、不上传，因为云端可能自动上传样本。

### 八、下载站与自动更新
- `https://padmate.download/` 是 Cloudflare R2 桶的自定义域名，放安装包、`.sha256` 和 `latest.yml`，**只放正式版**。没有网页：一个只路由 `/` 的 Worker 读 `latest.yml` 并 302 到最新安装包，路由不能是 `/*`，否则会挡在更新前面。
- 更新用 electron-updater，网址写在代码里，`channel` 必须写，否则 rc 构建会读 `rc.yml`。
- **只在用户同意时下载和安装**：不自动下载，不在退出时自动安装（会在画画时悄悄停掉映射），不做差量更新。检查每 24 小时一次，设置存在界面自己的目录，不进 config.json。
- 失败时给“手动下载”链接，因为浏览器能续传而 electron-updater 的下载不能（安装包约 135 MB）。
- **隐私：** 只请求 `latest.yml` 和安装包，Cloudflare 看得到 IP、`User-Agent: padmate/<版本>` 和文件名。
- **信任根：** 未签名构建只靠 `latest.yml` 里的 SHA-512，而它和安装包都来自下载站，所以信任根是能写桶或这个域名的人。

### 九、发布
`task release:r2` 由人运行，构建从不上传，不读凭据，用发布机上已登录的 wrangler。上传前拒绝预发布标签、对不上的 `latest.yml`、已发布过的安装包和不比站上新的版本。**顺序：安装包、`.sha256`，最后才是 `latest.yml`**，因为客户端和 Worker 跟着它走。GitHub release 继续发在公开的仓库上，预览版只在那里。

## 代价

- 未签名的安装包触发 SmartScreen“未知发布者”，每个版本从零积累信誉。
- 向导比一键式多按一次。
- 国内网络上 Cloudflare 没有保证。它的安全功能可能挑战不常见的 User-Agent，表现为“无法检查更新”，要给 `/latest.yml` 和安装包加跳过规则。
- 发布过的安装包不能覆盖，要改就发新版本。

## 放弃的做法

- **所选文件夹直接当安装目录，或去掉守卫只靠子文件夹。** 选了桌面就等于卸载时删桌面；用户也能选已有别的东西的 `padmate` 文件夹。
- **不试写，装不进去时由安装过程报错。** 用户会没有旧版本也没有新版本。
- **关界面时自动安装更新，或差量更新。** 前者在画画时停掉映射，后者要保留 135 MB 的副本。
- **用导入表做 PE 检查。** Go 的 exe 运行时才取 API，导入表看不出来。
- **带网页的下载页，或别的服务器当下载源。** 前者太啰嗦，后者太慢。
- **用 `taskkill`、PowerShell、wmic 按名字结束进程，或总是在 quit 后运行 `release-all`。** 会误杀开发版和便携副本，或让别处的 padmated 释放键并销毁脚本。
