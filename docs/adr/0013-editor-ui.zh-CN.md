# ADR-0013：编辑界面

[English](0013-editor-ui.md)

相关：[ARCHITECTURE §12](../ARCHITECTURE.zh-CN.md)；[ADR：映射模型](0012-mapping-model.zh-CN.md)；[ADR：进程与技术栈](0001-processes-and-stack.zh-CN.md)；[ADR：脚本宏](0011-script-macros.zh-CN.md)

## 背景

编辑界面是 Electron 应用（`app/`）。早期信息太多，内部词直接显示。用户是画画的人，要一眼看出每个键做什么。方向是做减法：界面只提供常用子集，格式和引擎保持能力（[映射模型](0012-mapping-model.zh-CN.md)）。

## 决定

### 一、页面与设置
- 导航只有映射、配置、脚本、设置。日志和诊断从设置页的“关于”进入。
- 设置修改即时保存。设置页每行最多一句说明。冲突软件提示（Steam、DS4Windows、HidHide）可关闭，“没有手柄”页不可关闭。

### 二、手柄图
- 用真实的开放许可 3D 模型（CC BY 4.0，署名在 `app/src/renderer/controller/assets/ATTRIBUTION.md`），固定正面不可旋转，主页面不滚动。
- 每个物理控件一条引线和一个原生 HTML 按钮，键盘可达。摇杆是上下两格“旋转”“点按”。
- 标签按当前手柄 SDL 报告的按键给（`buttonMask`、`axisMask`，`padHasControl`）：手柄没有的键不给，比如横握的单只 Joy-Con 没有十字键、右摇杆、扳机和 −。附加键（Share、Capture、麦克风键、Elite 和 Edge 的背键、Edge 的 Fn 键、Joy-Con 的 SL/SR 或横握时的 L/ZL）在手柄下方排成一排，左手的在左、右手的在右，整排夹在两列标签之间。SDL 还没报告按键时按标准手柄给，PS4、PS5 另有触摸板。外形有四种：PS5 用 DualSense，PS4 和 PS3 用 DualShock 4，Joy-Con 用 Joy-Con 的模型，其余（Xbox、Switch Pro、未知手柄）借用 Xbox。横握的单只 Joy-Con 横着显示，直握的竖着显示。左右两只同时连着时是一个完整手柄（SDL 自己合并），并排显示成一对。
- CSP 保持 `connect-src 'none'`，所以模型解码不用 `fetch`，也不依赖外网。
- 渲染舞台在应用会话里常驻，再进映射页只是把 canvas 放回去，仅在换模型、context 丢失或失败时释放，因为耗时主要在纹理上传。

### 三、按键抽屉
- 动作类型只有“快捷键”和“脚本”，映射只有点按、长按、双击。细节点开才看。
- 删除就是真的删除。从没设过的键先给一个空的“点按”，不录入就不写进文件。
- 名称跟着映射走。“功能”（绑定的 `label`，或摇杆的 `analog.ls.label`）在这个键有动作（或屏蔽）之前不能填；一次修改让这个键或这根摇杆什么也不映射了，名称一起去掉，什么都不剩的绑定整个去掉。摇杆算有映射：它移动鼠标，或者它在当前模式下发的键（方向，或旋钮的两个刻度）、内外圈、原始半轴里有一个带动作，正好是它的标签不显示“未设置”的时候。摇杆“旋转”格没有自带的名字：没写 `label` 时像普通按键一样，标题是它的键或动作，不再用模式名（“方向键”“旋钮”）。
- 按键按手柄上印的名字显示，不能改名。旧界面写下的键名 `controlNames` 退役，和反馈开关（ADR-0015）、ADR-0008 从 config.json 退役的成员一样：守护进程和 `padmatectl validate` 照常接受，检查照旧、不给警告，但谁也不读它；界面每次保存这个配置时去掉它（`savedForm`）。它是配置的一个成员而不是某个键，去掉它不改任何绑定；只打开不改不重写。导入 AntiMicroX 配置不再写它（报告里说明名字没有导入）。
- 文件里可能已经有只有名称、没有动作的绑定（手写的，或旧版本留下的）。不改写它：守护进程给警告（“binding has no action”，`padmatectl validate` 也打印），映射页现在显示这个警告而不再隐藏；用户下次修改这个键时名称去掉。保存只去掉这次修改碰到的，别的键逐字节不变。
- 文件里有界面不提供的写法时，动作类型不选中或带锁显示，保存别的键时逐字节不变，换掉前要确认。
- 配置设置收名称、绑定软件、默认判定时间和开关。

### 四、修改即保存，撤销只在内存
- 每次提交立即校验、带 revision 保存并生效，没有保存条。被守护进程拒绝的草稿不写盘，界面显示原因和“重试”。断线时没存下的修改留在内存，重连后文件没变就再存，变了以文件为准。
- 草稿是整份 profile，保存只替换编辑的部分。
- 撤销和重做只在内存里，每个配置最多 100 步，重启清空，配置文件在别处被改时清空。不用磁盘快照，因为快照粒度是保存，与一次编辑不对应。
- 关窗和托盘退出不丢最后一次修改：Main 请 Renderer 提交并等保存完成；托盘退出时守护进程先暂停映射并释放所有键，再等界面确认，最多 2 s。

### 五、快捷键录入
- 只有“录入”和“清除”，没有文字输入和 F13–F24 选择器。
- 键盘由短期的 `padmatectl keyboard-capture` helper 录：独立的 `capture.start` 连接所有权，专用线程上的 LL 观察钩子，不吞实体键，退出时关闭连接即释放。
- 鼠标键和滚轮由窗口自己看，窗口外看不到。
- 录到一个键（连同按着的修饰键）就结束。单按 Esc 录成 Esc，按住 1 秒取消。

### 六、快捷键对照表
padmate 只发快捷键，功能要用户在绘画软件里设到这些键上。“更多”菜单导出 Markdown 对照表帮忙。界面不替用户挑键，因为每个候选键都有已知冲突；也没有起始模板，新建配置就是空白。

### 七、按键预览与标签
窗口在前台时，执行动作的按下在映射页底部显示一行。标签只有“动作名称”和“快捷键”两种显示方式。

### 八、按键符号与图标
手柄按键的名字只有一个来源：`controllerLabels`，Go 的 `internal/padlabel` 照它写，测试比较两张表；手柄通过 SDL 报告的名字优先。

图标不自己画，用两套开放许可的现成矢量图标：Kenney Input Prompts（CC0，Xbox、PlayStation、Switch 三套，形状和印字照真手柄）和 PromptFont（OFL 1.1，只取 Kenney 没有的摇杆旋转和“任意方向”）。`pad-icon.tsx` 按 `controllerLabels` 给的印字和设备族选图标：面键、十字键、摇杆按下和方向按设备族用对应的一套，其余手柄用 Xbox 的；摇杆“旋转”格和旋钮刻度用 PromptFont 的旋转；PS 键画成 Home 的房子，不画厂商标志；横握的单只 Joy-Con 按位置画，不看 SDL 报告的字母。两套都没有的（斜向、推动阶段、Capture、附加键等）保留原来的徽标。同一套图标用在手柄图标签、抽屉标题、按键预览、设置页、诊断页和映射向导（向导问的是 SDL 标准布局，用 Xbox 一套）。图标的黑白取文字颜色、高亮取强调色，跟着界面配色走；强制颜色模式下保留两种系统色，否则十字键看不出方向。

素材来源和处理写在 `app/src/renderer/controller/pad-icons/README.md`，许可原文随文件放；“设置 → 关于与许可”列出两套图标并附 OFL 全文（OFL 要求随副本提供）。代价：渲染进程多约 100 KB 路径数据；小尺寸下 PlayStation 的 SELECT、OPTIONS 等字靠形状认。

### 九、配置页与软件选择
- 管理列表按创建时间排（取 NTFS 创建时间），固定的“默认”配置在最前。不用修改时间，因为每次保存都变。挑选列表按名称排，区域固定 zh-CN。
- 单个配置导出为 `.padmate`（zip，带用到的脚本）。守护进程生成和检查 zip，所有文件操作经 `os.Root`；Main 弹对话框、搬运字节，错误消息不带路径；Renderer 只传配置 ID 和 token。同名冲突时问“替换”还是“另存为/都保留”，默认焦点在不覆盖的一项。
- 添加软件有三种方式：点选窗口、从已安装软件选择、浏览，不能手动输入名称。规则按文件名匹配，不读窗口标题和应用内部状态。

### 十、设置文件自动修复
config.json 有错时，先备份成 `config.broken-<时间>.json`（从不覆盖已有备份），再写修复后的文件：保留合格的成员，每个错误只重置包含它的最小成员，完全解析不了才整个换成默认。界面弹对话框告知。备份或写入失败时修复只留在内存。state.json 出错静默重置。

### 十一、无障碍
- axe-core 在 Vitest 和真实 Electron 的 E2E 里自动检查，例外写在 `app/tests/a11y/exceptions.json`，每条要有理由。
- 对比度由读取 `theme.css` 的纯计算测试保证；强制颜色模式下各状态的样式要可区分。
- 对话框焦点不外逸，Esc 关闭并回到触发控件。

### 十二、界面和用户文档用同一套名字
文档里用“…”引起来的界面文字必须出现在 `app/tests/docs/names.ts` 的点名表里，点名表每一项必须在界面源码里是相邻的中英文一对。改了界面文字，要同时改点名表和文档。

## 代价

- Three.js 和五份 GLB（约 18 MB）增大构建产物，舞台常驻占一份 GPU 内存。
- 修改即保存没有“放弃”，误改靠 Ctrl+Z，撤销不跨重启。
- 手柄状态不明时，手柄发到 padmate 窗口的 Ctrl+Z 不会撤销。
- 坏设置文件被修复后，改掉的设置只能靠备份找回。

## 放弃的做法
- **按键图标自己画。** 不像真手柄，也不通用；改用现成的图标集。
- **只用一套图标集。** Kenney 没有摇杆旋转，PromptFont 不分手柄品牌，所以两套混用。
- **把 PromptFont 当字体加载，或用 `<img>`、CSS 遮罩显示 SVG。** 字体要带整个文件却只用六个字形；`<img>` 拿不到周围颜色，遮罩只能单色。改成解析出路径用 React 画。

- **原创几何手柄，或可旋转的 3D 视角。** 前者外观不被接受，后者不如固定正面加逐键引线清楚。
- **保存条加自动保存开关。** 开关只多一个状态。
- **映射页常驻、只隐藏。** 快捷键监听、焦点和无障碍树都留着，只保留渲染器这一层。
- **几个渲染器共享纹理，或只缓存解码结果。** WebGL 资源不能跨 context，解码只占 1 ms 级。
- **键池自动分配快捷键，起始模板。** 前者每个键都有冲突，后者与空白配置没区别。
- **坏设置文件整个换成默认，或只提示让用户自己改。** 一个拼错的字段会丢掉所有设置，也不能要求用户改配置文件。
- **在 profile.json 里记创建时间。** 要改 schema，而文件系统本来就有。
- **保存时去掉所有没有映射的名称。** 用户没碰的键会被改；警告能说明同样的事，又不改写它们。
- **Main 直接读写配置文件夹。** 路径检查要在两种语言里各做一套。
