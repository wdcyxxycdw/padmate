# ADR-0011：脚本即宏

[English](0011-script-macros.md)

相关：[ADR：脚本运行时](0010-scripting-runtime.zh-CN.md)

## 背景

早期的脚本是每个配置一个入口，整体接管按键，声明式绑定只能调用它注册的命名动作。用户要的是“按这个键，做一件事”。另外，界面第一次要往配置库写 profile.json 以外的文件，还要读用户用原生对话框选的文件。Renderer 没有 Node 能力，文件写入必须有唯一写者。

## 决定

1. **一个文件就是一个宏。** 脚本库 `<数据文件夹>/macros/` 顶层的每个 `.ts`/`.js` 是一个宏，默认导出无参函数，绑定的键触发时从头运行一次。绑定用动作 `{"type":"macro","file":…}`，没有参数和版本字段。宏只能用 d.ts 里标 `@macro` 的成员，不能注册处理器或活过一次运行。
2. **一次运行一个 owner。** 同一个宏在一个手柄上没跑完时，再触发不算。函数或它返回的 Promise 完成即结束：还按着的键松开，已交给 Arbiter 的点按照常按完。一次最多 60 秒。
3. **暂停、切换配置、重载、断连、紧急释放和退出都释放整个 runtime，包括正在跑的宏（不变量 1）。**
4. **每个宏文件单独构建，同一个 runtime 执行。** 一个文件出错不影响别的。每个手柄仍只有一个 goja runtime，共用生命周期、看门狗和输出限流。只有宏时 runtime 不接管输入，普通绑定的延迟不变。
5. **脚本库与配置无关。** 所有配置共用一个库，配置只写引用。改名和删除在库写锁内同时改所有配置里的引用，任何一步失败则全部改回。库的写操作经 `os.Root`，先要求名字精确出现在目录列表里，大小写、8.3 短名、链接、junction 都不会改到别的文件。
6. **导出带上脚本，导入时同名同内容复用，同名不同内容由界面问“替换”还是“都保留”。**
7. **界面新建和导入只由守护进程写文件。** Electron Main 选文件、读文件（上限 1 MiB，严格 UTF-8），Renderer 只拿到相对文件名，没有路径。同名替换用一次性 token：Main 把读入的内容留在内存，确认时写当初读入的那一份，不重读文件，也不接受 Renderer 给的路径。

## 代价

- 宏没跑完时再按会被忽略，要在按住期间持续做事的效果，宏做不了。
- 某个宏被看门狗打断时，整个 runtime 退避重启，这个手柄上的宏和旧式脚本都被打断；被打断的宏停用到它的文件改动为止。
- 前台程序切换配置时，正在跑的宏被打断，包括宏自己按 Alt+Tab 引起的切换。
- 改名或删除时 profile.json 和文件分两步写，中途失败可能留下找不到的引用，界面显示“找不到”。撤销或恢复历史版本也可能带回这样的引用。
- 导入的脚本没有信任确认，风险和导入别人的脚本相同。
- 导出按文本里的相对 import 找模块，找不到计算得到的路径。

## 放弃的做法

- **多个入口脚本同时运行。** 抢同一个键时的先后规则要另定，也不是用户想要的用法。
- **所有宏合成一个入口打包。** 一个语法错误让所有宏不能用，也分不清输出属于哪个宏。
- **每个宏一个 runtime。** 每个手柄多份 runtime、冷启动和看门狗，内存和代码翻倍。
- **同一个宏运行时再触发时排队或重新开始。** 排队让长宏晚几秒又跑一遍，重新开始会留下半截效果。
- **运行结束时取消 owner 的一切。** 没 await 的最后一个 `key.tap` 会被截短，还会提前松开别的 owner 的键。
- **脚本按配置分开存放。** 同一个脚本要存多份，页面也看不到其他配置的脚本。
- **导入时同名一律替换或一律保留。** 替换改变别的配置的行为，保留让库里堆满副本。
- **Renderer 自己读文件，或确认替换时按路径重读。** 复用不了 Main 的检查，确认的和写入的可能不是同一个文件。
- **“编辑”用 `.ts` 的默认程序。** 在 Windows 上常打开视频播放器。
