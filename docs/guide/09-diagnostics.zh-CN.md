# 诊断

[English](09-diagnostics.md)

按了手柄键却没反应？诊断页告诉你 padmate 对这次按键做了什么，没做则说明原因。

## 打开诊断页

左边点“设置”，在最下面的“关于”里找到“诊断”一行，点“查看”。回设置页点页面顶部的返回按钮，或按 Esc。页面有“事件”“延迟”和“冲突”三部分。

## 事件

“事件”列出这次连接以来最近 200 次按键，最新的在最上面。每一行从左到右是：时间，手柄的名字（连了两只以上手柄才有），按下的键，映射（“点按”“长按”或“松开”），用的哪一套设置（“平时”“按住功能键”“共用”或“脚本”），以及结果。发出快捷键时结果写动作，没发出时用一句话说明原因。

结果旁边可能有两个标记：

- “只预览”：这个动作没有真的发出去。映射服务在演练模式，或 padmate 自己的窗口在前台时，就是这样。
- “等了 N ms”：这个键为分清点按、长按或连按，等了这么久才触发。

页面上方有“筛选按键”（只看一个键）、“只看没有动作的”、“暂停记录”（再点一下变成“继续记录”）和“清空”。

## 常见的原因

结果一栏里最常见的几句话：

- “当前配置里这个键没有设置动作”：这个键在当前配置里是“未设置”。给它设快捷键，或看看当前配置是不是你以为的那个。
- “按下时没有动作，要等松开、长按或连按后才能确定”：动作在后面，不是问题。
- “映射已暂停”：窗口顶部是“已暂停”。点“恢复映射”。
- “系统暂停中（锁屏、睡眠或安全桌面）”：回来以后自动恢复。
- “这只手柄被设为忽略”和“这只手柄没有标准映射”：这只手柄没有被映射。没有标准映射的手柄可用[映射向导](11-mapping-wizard.zh-CN.md)建一份。

诊断页上完全没有新行，说明 padmate 没收到这个键。检查手柄是否连着，再看下面的“冲突”。

## 延迟

“延迟”按手柄列出 padmate 从收到输入到发出按键用了多久：样本数，然后是 p50、p90、p99 和“最大”。p99 超过阈值（默认 1.5 毫秒）时会出现标记。

## 冲突

“冲突”列出可能占用手柄的软件：Steam、DS4Windows 和 HidHide。有软件在运行时，这里写“Steam 正在运行”之类的提示和处理办法。

没有检测到这些软件时，这里写着“没有检测到可能占用手柄的软件。”
